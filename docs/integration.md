# 兼容版 cccodroid 集成与协议边界

仓库中的网关适配器与面板是现有会话托管功能的源码快照，**不是**可直接应用到官方 cccodroid 的补丁。移植时必须同时实现宿主侧的生命周期与权限检查，不能只把面板挂到网页上，也不能把原生网关暴露到公网。

## 三个角色

- **主机**运行原会话并选择可共享的 SID。`HostingEngine` 从主机适配器取得有限的历史、增量、状态和许可卡；所有真实操作都在主机发生。
- **控制端**通过同源网关请求已配对的主机。浏览器面板不直接发中转请求，不能依赖浏览器 CORS 放行或共享明文凭据。
- **中转**认证房间的两类传输凭据，并转发密文。在 `/cc-host/v1` 提供健康检查、注册及撤销、主机轮询和回复、控制端请求。它不是终端、文件、HTTP 代理或模型服务。

主机和控制端通过配对共享房间密钥，信封使用 AES-256-GCM，认证数据绑定房间、请求编号和方向。生产模式只接受无路径、用户信息、查询和片段的 HTTPS origin，不跟随重定向；测试引擎才显式接受回环 HTTP。中转不接收配对码或会话密钥，但 TLS 终点仍是传输凭据的信任边界。

## 网关接入条件

- `index.mjs` 必须挂在宿主现有 Host/Origin 和本机认证之后，`/api/hosting/*` 不是公共端口。保留无缓存响应；不要把状态和配对接口交给公网反代。Android 原生壳对已验签的状态请求有单独的托管保活逻辑，本仓库不带原生壳。
- 网关拿到主端口后再读取和恢复托管；回收恢复须先确认文件状态、恢复队列，再重放回收通知。`TRASH_HOOKS` 中的托管撤销是同步的；持久化失败要保留事务供重试，不能在同号副本仍有歧义时丢掉撤销依据。恢复同号会话不能自动恢复旧授权。
- `adapter.mjs` 依赖宿主的会话索引、历史页、运行、队列、书签和鉴权后的提交点。把 `hostingCheck` 传到这些提交点，在读请求体、计算历史范围等异步步骤后，于真正写入或执行前再次确认授权。测试里用内存适配器代替这些宿主模块；它不是一个可以转发任意操作的模板。
- 主机的 `list/session/watch` 只返回当前可共享的会话；写操作还核对当前主机世代与会话授权。发文字、停本轮和回复单次许可都有明确作用域。支持消息操作的宿主还会核对历史修订和消息归属。主机先持久化请求编号再执行，回执不明时刷新状态确认，不自动换新编号重发。

## 面板接入条件

- 在已集成的网关中，同源加载 `panel.css` 和 `panel.js`。面板依赖宿主的工具/侧栏入口和 `window.__cc.chatSource` 生命周期，并使用宿主布局注册。官方 cccodroid 不保证暴露这些接口。
- 远端快照只用作远端会话渲染。保留本机与远程数据来源的区分：禁止将远程会话路径用于本机文件加载、终端、预览、安装或系统级动作。切换设备或会话时要取消旧请求，防止迟到回复写入新视图。
- 控制端应清楚标示主机不在线、授权失效、请求结果不明或摘要截短的情况；不可把仅删除本机配对记录显示成中转已确认吊销。

## 如何验证

先跑仓库根目录的测试。回环联测用真实的 Python 中转和两个相同的 Node 引擎，模拟的只是会话生成与执行端。移植完整 Android 宿主时，还应另验两台设备的配对与撤销、暂停/重启、会话回收和来源隔离，不能把回环测试当成已通过实机验收。
